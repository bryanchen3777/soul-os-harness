## 3. 承諾生命週期閉環契約（決策 D1：新增 B6，不擴展 B1）

### 3.1 閉環後的完整生命週期

```
B1 種子命中 → ACTIVE → IN_PROGRESS → COMPLETED + sediment_completion    [既有, = 達成]
                                └→ ABANDONED（timeout 逾期）             [既有]
                                        │
                                        ▼
                終態承諾 → B6 閉環源（新種子, bryan 軸）← §3.3
                                        │
                                        ▼
                關懷/回報 goal（ACTIVE）→ volition path → transmit      [§4, 禁止直發]
```

- **達成判定 = goal COMPLETED 既有沉降鏈即為達成**（`_completion_met` → COMPLETED + `sediment_completion` 沉澱，0 新判定）。
- **逾期判定 = deadline 過期 → ABANDONED**（既有 `apply_interrupt_signals` 轉移，0 新判定）。
- 承諾閉環 = 在既有終態之上加**讀側回饋源**，0 改狀態機、0 改轉移表、0 新表。

### 3.2 決策：哪些承諾狀態變化應成為 B 軸種子源 → **新增 B6（commitment_closure）**

**候選方案對比：**

| 方案 | 做法 | 判定 |
|---|---|---|
| **A（採納）新增 B6 獨立源** | SEED_ROTATION 加第 10 源 `{key:"commitment_closure", axis:bryan}`（插在 B5 之後、S1 之前）；掃描本窗內進入終態的承諾類 goal → 產出「關懷/回報」種子 | ✅ 最小 additive：一個 probe 方法 + 輪序常量 +1；ref 命名空間獨立；0 動既有結構 |
| B 擴展現有 B1 commitment 源 | `_probe_commitment` 同時管「現況 → 新承諾」與「終態 → 回饋」 | ❌ 兩件不同語義塞一個 probe：B1 ref=`relationship:user_bryan`（關係維度）與回饋 ref（goal 維度）無法共用單一 SeedHit.ref；需改 SeedHit 結構或 probe 多重返回 → 動到 LS-2 已驗證結構，非最小 |

**理由（最小方案採納 A）：**
1. **語義正交**：B1 = 「現況」源（現查 relationships → 開新承諾）；B6 = 「閉環」源（終態承諾 → 收尾回饋）。兩者合流會讓單一 probe 的素材/冪等語義互相污染（現況重複追蹤 vs 結局一次性回饋）。
2. **冪等鍵獨立**：B6 的 ref = `commitment_closure:{goal_id}`（goal 維度，一個終態承諾至多一次回饋）；與 B1 的 `relationship:user_bryan`（關係維度）正交，互不影響去重。
3. **窗口判據天然**：「本窗（last_seed_scan_at → now）內 state_updated_at 進入終態」是純結構規則（§3.3），無需引入任何額外狀態；擴展 B1 則需要為「回饋已做過」另造判據。
4. **未來寫側 0 連鎖**：LS-2 寫側啟用 `commitment:{id}` 命名空間後（LS-1 §3.3），B6 靠命名空間前綴識別（§3.3 第 2 項）自然涵蓋新命名空間，probe 0 改動。

### 3.4 閉環時序範例（一個承諾的完整一生）

以「B1 承諾種子：找機會關心 Bry 上次提的工作面試」為例：

| 階段 | 時刻 | 動作 | 產物 |
|---|---|---|---|
| 1 種子 | 某日白天 | B1 現查 relationships → 方案 B 語義化 → upsert_goal | goal X: bryan, ref=`relationship:user_bryan`, criteria {interaction, 2, 7d}, ACTIVE |
| 2 推進 | 之後數日 | Decision 兩度選中商談/關懷（進 IN_PROGRESS, advance_count=2） | `_completion_met` → COMPLETED + `sediment_completion` 沉澱（goal 級） |
| 3 閉環 | 隔窗（≥24h 節流） | B6 掃描：X 的 state_updated_at ∈ 窗口、ref 前綴 `relationship:` → 產回饋種子 | 回饋 goal Y: bryan, ref=`commitment_closure:{X}`, criteria {interaction, 1, 7d}, ACTIVE |
| 4 反饋 | 再下一窗（尊重輪替/相位/Decision） | Y 進候選池 → 四元 Decision → transmit 命中 → 關懷傳達 | 既有 AGENCY_TRIGGER publish（唯一出口） |
| 5 收束 | 之後 | Y 被推進 1 次 → COMPLETED；或 timeout → ABANDONED（皆既有） | 回饋亦沉澱，閉環完成 |

若階段 2 未達成（7 天超時）→ X 直接 ABANDONED（既有），階段 3 素材語義為「逾期釋懷」——**途徑完全一致**，僅語義化輸入的終態標記不同。

## 4. 反饋機制契約（決策 D2：volition path，禁止直發）

### 4.1 全程路徑（唯一合法反饋路徑）

```
B6 種子命中（§3.3）
  └─ upsert_goal(ACTIVE, bryan, ref="commitment_closure:{goal_id}")        [建池, 0 直發]
       └─ assemble_candidate（既有 24h/1 窗 + 雙軸輪替 + 冪等）→ make_motive
            └─ decide_motive（SM-4 四元互斥 Decision, 社交摩擦力 + 深宵硬禁止既有）
                 └─ transmit 命中 → 既有 AGENCY_TRIGGER publish 鏈（四元已過, 唯一出口）
                 └─ observe / reflect / do_nothing → 不發布（回饋自然消解或延後）
```

- **禁止直發清單（0 例外）**：終態承諾、其素材、或其關懷 goal **不得**直連 publisher / DiaryHandler / tool_registry / Telegram 通道 / 任何 AGENCY_TRIGGER 之外的發布路徑；不新增任何「專門回饋」的執行通道。
- 反饋與一般 goal 完全同權：也受 `consecutive_do_nothing` 信號 6（連續不傳 → SUSPENDED）與雙軸輪替約束——**回饋是候選不是指令**，Bryan 不回應 = 回饋自然消解，0 升級騷擾。

### 4.2 繼承的既有防護（0 新實現）

| 防護 | 繼承來源 | 作用 |
|---|---|---|
| 24h 節流 | `GOAL_QUOTA_WINDOW_SECONDS`（scan_seeds 節流 + assemble 候選窗） | 回饋種子 ≤1/24h/agent；與 9 源共享配額 |
| 作息相位抑制 | `_bryan_axis_suppressed`（quiet 23-08 / last_seen>4h） | B 軸（含 B6）在夜間 / Bryan 離開時不產種子 |
| 四元 Decision | `decide_motive`（SM-4 + 社交摩擦力 + 深宵 [22-07] 硬禁止） | transmit 是唯一發布出口，且需過完整意願審查 |
| signal 6 / 輪替 | `apply_interrupt_signals` / `_pick_axis` | 回饋 goal 也受「連續不傳掛起」「同軸 ≤2」約束 |

### 4.3 反饋不升級不變式

回饋機制不是「提醒升級器」，契約鎖定三條不變式（TL-11 A2 硬斷言）：

1. **一次終態一次回饋**：`commitment_closure:{goal_id}` 冪等（窗口判據 + 非終態去重），無重複提醒、無升級頻率。
2. **回饋同權於一般 goal**：無專屬優先級、無提升配額、無繞過四元的路徑——Bryan 不回應時，回饋自然經 signal 6 / timeout 消解，0 追擊。
3. **回饋內容不承載打分**：素材只含結構事實（終態、次數、時點），「該不該內疚 / 有多重要」等評判 0 進入種子；語調由語義化 LLM 生成（既有的「不編造素材外事實」紀律）——No-Scoring 在回饋語義上同樣成立。

## 5. 週期敘事昇華契約（決策 D3/D4/D5/D6/D7）

### 5.1 掛點與觸發（0 新定時器、0 新 payload 通道）

- **掛點**：scheduler 主循環 30s wake 內、night slot（22:00, `_slot_for_time(now)=="night"`）檢查鏈的 **additive 分支**（與 `_fire_all("night")` / `_goal_scan_all` 並列，0 新 asyncio timer / cron / tick / sleep）。
- **判據（night slot 當晚檢查，結構規則）**：
  - **週記**：當前 ISO 週 key（`YYYY-Www`）無既有沉澱（trace 判重，§5.4）→ 觸發；已沉澱 → 跳過。**頻率目標：1 次/週**（ISO 週判據天然 ≥7 天間隔；每週至多 1 次）。
  - **紀念日**：今晚存在「事件日 == 今天（本地 YYYY-MM-DD）」的 accepted calendar_event（perception_trace 內 `event_type=="calendar_event"` 且 `accepted is True`，白名單 `WORLD_QUALIFYING_TYPES` 既有產物）→ 觸發；否則 0 動作。
- **不是每日產物**：兩者都是「條件觸發 + 一次沉澱」；diary（morning/night 日拍）與週記（週粒度）正交，0 重複（LS-1 §5.2 已聲明）。

### 5.2 週記聚合規則（read-side，0 新存儲）

- **聚合窗 = 當前 ISO 週週一 00:00 → 觸發時刻**（本週至今）。
- **聚合源（身分防火牆 §5.5 過濾後）**：
  1. 自己的 diary 條目：`data/soul/{agent}/diary/YYYY-MM-DD.jsonl`（窗內日期檔，`ts/slot/content` 全量聚合）；
  2. 自己的 InnerLifeEvent/trace：窗內本 agent 的事件（diary/dream/conversation 類，歸屬判據 §5.5）；
  3. 本週 goal 終態：goals 表 `state_updated_at ∈ 窗` 的 COMPLETED/ABANDONED goal title（承諾閉環的回顧素材，0 新狀態）。
- **全聚合不挑選**：窗內命中素材全部進語義化輸入（週記 = 該週共同生活的完整重構，不做「選哪件事」的挑選；LLM 只做敘事重構，不決定取捨範圍）。
- **語義化**：方案 B 既有 proxy 通道（與 seed_provider._semantize 同款），產出「共同生活故事」敘事；失敗 / 空輸出 → fail-closed 跳過本週（0 半成品）。

### 5.3 紀念日反芻規則

- **觸發依據**：§5.1 判據（既有 calendar_event 白名單產物，0 讀新 world 源）。
- **聚合窗 = 往年今日（同 M-D 不同年）的 diary 條目**（按年份翻查歷史 `diary/YYYY-MM-DD.jsonl`）+ 該 calendar_event 的事件標題（作為上下文物引用，非經歷素材）。
- **聚合空 → fail-closed 不沉澱**（log debug；紀念日本身極少、往年資料稀疏為預期）。
- 目的：把「今天為何特別」接回自己活過的證據（去年/前年今天的心境），重構為週期性自我回望——**身分防火牆同 §5.5**（只聚合自己的往年 diary，不引用他者記憶）。
