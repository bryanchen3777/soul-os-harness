## §1 目标与非目标

### 1.1 目标（一句话）

> transmit 且 motive.target 明确指向某他者（bryan 或 agent）时，把该他者在 `relationships.json` 4.2 的关系带 + 印象标签投影进 Expression prompt（proxy 组装层），让 LLM 的措辞/语气自然随熟悉度分层——陌生伙伴客气疏离、熟悉伙伴熟稔亲近；无关系条目时整块省略（fail-safe）。

### 1.2 分层目标（可验证的现象）

| 层 | 行为 | 验证方式 |
|---|---|---|
| 注入层（v1 硬门槛） | 面向 target 的发言 prompt 内含 target 的 band + ≤5 tags；无条目省略 | 单元测试断言（§7） |
| 表达层（长期观察，不设硬门槛） | 语气层次在真实 LLM 输出中「可闻」（stranger 客气 / familiar 亲近） | TL-5 式长程观察（§7.2） |

### 1.3 非目标（红线，0 越界）

| # | 非目标 | 说明 |
|---|---|---|
| 1 | **不写静态语气指令表** | 不写「对 stranger 要客气」「对 close 要亲近」类规则句。注入只呈现关系事实（band + tags），语气由 LLM 自己推理（对齐 CA-2「Definition → projection → LLM context，不携带『应该』语义」先例，`SOUL-CAPABILITY-AWARENESS-DESIGN.md:60-62`）。 |
| 2 | **不建打分/权重** | 0 浮点权重、0 数值亲密度、0 排序（对齐 SG-1 §6 No-Scoring：band 只回答现象学距离，不进入任何算式）。注入信息本身 0 语义权重。 |
| 3 | **不改 10 份 persona 档** | 人格文件 0 触碰（对齐 TA-1 先例：「不改 10 份人格档」，`proxy.py:627` 注释）。 |
| 4 | **不做新投递通道** | 0 新 DM 通道、0 新 EventType、0 新 trigger_type（SG-1 §5.3 定死：复用既有公开频道）。 |

## §4 渲染格式与 Token 预算

### 4.1 块格式（v1 定稿，确定性渲染）

```
[關係感知]
- 對 {target_id} 的關係帶：{band_label}
- 印象：{tag1}、{tag2}、{tag3}
```

- **band_label 映射**（对齐 SG-1 §3.1 四带语义，0 数字）：

| band 值 | 标签 |
|---|---|
| `stranger` | 陌生人 |
| `known` | 認識 |
| `familiar` | 熟悉 |
| `close` | 親近 |

- **印象行**：`impression_tags` 至多前 5 个，`、` 连接；空列表 → 省略印象行，只留关系带行。
- **不输出**：`confidence`（D4 冻结只读）、`interaction_count` 等计数、band 序号、任何分数。
- **反框架提示**：块尾**不加**使用说明句——本块是「面向 target 的确定性事实」，与 M5.13-3 同风格（纯事实陈述，`proxy.py:374-379`）；不加指令句（非目标 #1）。
- 语言：块内文案用繁体（对齐系统块风格：`[當前時間感知]`、`[你跟 Bry 的關係]`）。

### 4.2 Token 预算（硬上限 ≤80 tokens）

- **上限**：整块渲染后 ≤80 tokens（CompactSocialState ≤150 tokens 先例的一半，`aggregator.py:151`；工单指定 ≤80）。
- **自然上界论证**：格式固定 = 2 行头 + 1 行 band（~20 tokens）+ 印象行（5 个 tag ≈ 5×8=40 tokens 上限），最坏 ≈60-70 tokens；单 target 单块，无多他者铺开。
- **实现护栏**：helper 内 `MAX_IMPRESSION_TAGS = 5` 截断 + tags 单项长度截断（单项 `[:12]`，防 LLM 长 tag）；渲染后无需二次量词校验（结构保证），但测试断言 `len(tokens) <= 80`（§7.1 Q4 近似：字符数 / 2 或直接按 tokenizer 估算）。

### 4.3 注入范围决策（与 M5.13-3 的差异，契约钉死）

| 维度 | M5.13-3 `_format_relationship_block`（既有） | C-3.1 `_format_relational_perception_block`（新） |
|---|---|---|
| 目标选择 | Bryan + top3 其他角色（全量投影，`proxy.py:442-474`） | **仅当前 motive_target 单个**（面向谁就注入谁） |
| 数据域 | 旧 confidence 数值层（0.3/0.5/0.7 阈值映射，`proxy.py:345-350`） | **4.2 新语义域**（relational_band + impression_tags，SG-1 D4 唯一真值） |
| 注入条件 | confidence ≥ 0.3 才输出（stranger 不输出） | **有 entry 即输出**（stranger 也注入——正是「对陌生伙伴客气疏离」的机制） |
| 位置 | mood 之后 inner_life 之前 | 同槽位（紧邻其后，见 §2.2） |

- **两块并存**（v1）：0 改动 M5.13-3 块（既有测试锚点 `test_m5_13x` 不回退）；两块的 band 标签可能不一致（旧块看 confidence、新块看 relational_band）——**已知边界点，诚实标注**：M5.13-3 是 legacy confidence 视角的保留投影，C-3.1 是 4.2 语义的正式消费；实现期不统一（0 破坏优先），文档建议后续工单评估 M5.13-3 块迁移到 4.2 数据域（显式列为 additive 待办，本工单不做）。

## §5 No-Scoring 与 Volition 边界

### 5.1 注入是 context 信息，不是权重（核心不变量）

- 本块 = LLM context 里的一段**事实陈述**（band + tags），与 `[你記得以下這些事情]`、`[你跟 Bry 的關係]` 同类（`proxy.py:578-579,588-590`）。**0 权重、0 数值、0 排序、0 乘法因子**（对齐 SG-1 §6.1：拒绝 affinity=0.82 型数值；band 只回答「现象学距离」）。
- 与 CA-2 anti-runaway 同精神（`SOUL-CAPABILITY-AWARENESS-DESIGN.md:127-128`）：块是「我知道和他是什么关系」，不是「所以我应该怎样说话」——不携带任何「应该」语义，措辞由 LLM 从事实自然推出。

### 5.2 Decision 四元互斥与先后序（0 影响）

- 时序钉死：`decide_motive`（Decision 层）**先于** Expression 注入（`scheduler.py:432` decide → `:441` transmit 判定 → 才走投递链）。本块只出现在 transmit 确认后的**发言生成**环节，`observe / reflect / do_nothing` 路径 0 接触（四元互斥不被注入影响）。
- **表达式注入 0 影响 Decision**：本块不进入 `build_decision_prompt`（`decision.py:187-313` 四块结构 0 触碰）；Decision 看到的 target 感知 = 既有 `motive_block` target 呈现 + 关系摘要（§5.3 边界说明）。

### 5.3 既有约束优先级不变（深夜克制等）

- Decision prompt 的深夜克制 / 低亲密度克制 / 留白分布（`decision.py:273-306` Boundary 文本）**一字不改**——它们决定「发不发」；本块只影响「发了之后怎么说」。两个层面正交。
- 深夜 transmit 被禁时（22:00-07:00 绝不 transmit，`decision.py:288-292`），本块根本不会被触发（无 transmit 即无 Expression）——优先级链自然保持。

### 5.4 Decision 层边界声明（诚实呈报项，非本工单改动）

- 取证发现：`_build_relationship_summary`（`decision.py:393-424`）硬编码读 `user_bryan` entry（`decision.py:405`）——agent-target motive 进入 Decision 时，关系摘要块（`decision.py:250-251` "你与 {target} 的关系"）实际填充的是**与 Bryan 的关系**，而非与目标 agent 的关系。这是 Decision 层既有缺陷（SG-2 只解冻了 target 值域，未同步关系摘要取值）。
- **C-3.1 处理**：0 触碰（本工单范围 = Expression 注入；改 `_build_relationship_summary` 属于 Decision 层，且会触碰 `decision.py` prompt 组装逻辑 = DECISION-PROMPT 契约面）。**呈报主大脑**：建议后续工单将 `_build_relationship_summary(agent_id, target)` 改为按 target 取值（additive 参数，缺省 user_bryan 向后兼容）——列为「需 Owner 知悉」项而非本工单拍板项（§9.2）。
