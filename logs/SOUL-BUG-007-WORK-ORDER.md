## 目標

修掉兩個都屬「寧可誠實說不知道，也不能亂答」的檢索缺陷。

## 缺陷 A：簡繁字形分裂（召回損失）

繁體 persona 管線裡混進簡體寫入的 tag（全庫約 323 處）。

**決定性證據**：同一個 `agent_aoi` store，繁體與簡體查詢結果不等。

| 查詢 | 修復前 | 修復後 |
|---|---|---|
| `評價`（繁） | 2 筆 | **7 筆** |
| `评价`（簡） | 5 筆 | **7 筆** |

也就是說繁體查詢**漏掉 60% 該找到的記憶**，純粹是字形不同。

**修法**：`_expand_tag_components` 內做簡→繁轉換。
- 選這個位置的理由：它是 query 端與 memory 端的**唯一共同展開點**，
  在此轉換即可讓兩端字形一致，且**完全不碰 frozen 的 `writer.py`**。
- **刻意不放在 `derive_query_tags`**：它同時被 frozen 的 `writer.py:722` 用來產生
  新寫入的 tags，在那裡轉換等於間接改變 frozen writer 的輸出。

**依賴現況**：`.venv` 未安裝 opencc / zhconv / hanziconv（已實測）；
repo 內 `src/llm/translate.py:265` 只有 14 字的區域性過濾清單、**沒有對應表**，
無法複用。故採 305 條輕量內建對照表，**未收錄的簡體字仍不會被正規化**
（誠實揭露的覆蓋缺口）。

## 缺陷 B：泛化謂語／話語支架詞單獨開 Gate（假召回）

問 `agent_yua`「你喜歡看書嗎」，庫裡根本沒有「書」，卻因命中「喜歡」而召回
**5 筆「你喜歡聽…」的離題記憶**。

**為什麼這比召回率低嚴重**：低召回是誠實的（回空＝我不知道）；
假召回會讓角色一本正經地說錯話。

**語料實測支撐**（writer 的 `{subject} {predicate} {object}` 機械組裝產物）：

| token | 全庫 df | 性質 |
|---|---|---|
| 說話者 | 417 | 話語支架（是誰在講） |
| 對方 | 298 | 話語支架 |
| 一直 | 153 | 泛化謂語（謂語槽佔比 0.56） |
| 記得 | 60 | 泛化謂語（謂語槽佔比 0.83） |
| 知道 | 47 | 泛化謂語（謂語槽佔比 0.81） |
| 喜歡 | 39 | 泛化謂語（謂語槽佔比 0.54） |

**修法**：收編進 `_LOW_INFO_TOKENS`，成為 SAGE-RANK-1 的 Secondary Boost。
- Gate 側：單獨命中無法開門 → 問「看書」回 0 筆（誠實）。
- Boost 側：同時命中真主題時，「喜歡讀書」得 +1.0，浮到「喜歡聽」之上。

### 為什麼不用「卡 IDF 絕對下限」

IDF = `ln((N+1)/(df+1))+1` 隨各角色庫大小劇烈浮動：小庫 `N=30` 的專有名詞
（df=2）IDF 只有 3.33，而大庫 `N=1007` 的高頻廢詞（df=66）IDF 就有 3.71。
固定門檻要嘛殺死小庫的真記憶，要嘛放過大庫的支架詞。

### 刻意不收的三類（本案最易做錯處）

1. `顏色` —— yua 的真主題（df=22），問「你最喜歡的顏色」必須召得回。
2. 角色專名（瑠夏 109／雷姆 213／真昼 185／三玖 20）—— **df 高不代表零區辨力**。
3. 泛化謂語的**受詞**（書／口味／顏色）—— 那才是主題本身。

## 驗收

- 17 項新守衛測試 ＋ 14 組變異實驗全紅。
- 生產 10 store × 常用主題詞的退化掃描：**合計 delta = +0**。
- 被 Gate 丟棄的記憶逐筆查核，**全部只命中泛化謂語**（例：問口味卻回
  「我喜歡看你吃的樣子」），確認是離題而非誤殺。
